# CDP Workflow Details

## Runtime Model

- SeaShort is the Electron host app.
- The current `.animeproj` root is a Vite React project.
- SeaShort starts the project through Vite and renders it inside an Electron preview frame.
- Agent automation should attach to the Electron renderer through CDP, inspect targets/frames, then select the non-host local frame that belongs to the current preview.
- Host and preview ports vary by environment. Treat common ports as hints only; use `inspect` output as the source of truth.

## Expected Electron Setup

The Electron main process should run before `app.whenReady()`:

```ts
if (isDev && process.env.SEASHORT_CDP_PORT !== '0') {
  app.commandLine.appendSwitch('remote-debugging-address', '127.0.0.1');
  app.commandLine.appendSwitch('remote-debugging-port', process.env.SEASHORT_CDP_PORT ?? '9222');
}
```

After restart:

```bash
curl --noproxy '*' http://127.0.0.1:9222/json/version
```

Use `--noproxy '*'` when local proxy env vars are set.

## Runtime Descriptor

SeaShort writes `.seashort/runtime.json` while the WebIDE preview is running. The CDP script reads it before falling back to port heuristics.

Useful fields:

- `cdp.port`: current Electron CDP port.
- `preview.url` / `preview.frameUrl`: current preview frame URL.
- `vite.url`: live Vite dev preview URL.
- `staticPreview.url`: post-build static preview URL.

Do not edit this file by hand or store its port values in durable docs. It is runtime evidence.

## Command Notes

- `eval`, `html`, `snap`, `net`, `click`, `demo`, and `lifecycle` default to the detected SeaShort preview frame.
- `descriptor` is the first command to run when target selection looks wrong. It merges `.seashort/runtime.json` and environment overrides.
- `doctor` is the default one-shot health probe after code changes. `doctor.ok` only fails on blocking problems such as runtime exceptions, failed requests, Vite overlays, missing engine state, or layout errors; heuristic layout warnings stay in `warnings` and `layout.summary`.
- `logs` only captures CDP events that occur during its collection window. If you need startup errors, reload the preview or trigger the failing action while it is running.
- `engine-state` prefers `window.__SEASHORT_DEBUG__`, then falls back to `window.__engine`.
- `viewport-suite` saves screenshots under `.verify-shots/` and includes layout-audit summaries for each preset. Its `ok` status follows layout `errorCount`, not heuristic warning count.
- `audit-layout` is heuristic evidence. Use it to find likely overflow, clipping, overlap, token misuse, and accessibility basics; confirm visually when the report is ambiguous.
- `snap` is an auxiliary accessibility-tree probe; Electron/iframe accessibility output may be shallow. Use `html`, `inspect`, or `eval` when you need precise iframe DOM evidence.
- `clickxy` and `type` use raw CDP input events against the page session. Use them after focusing the right element, especially when DOM `eval` is blocked or iframe focus matters.
- Screenshots are saved under `.verify-shots/` unless an absolute path is passed.
- Screenshot pixels may be device-pixel scaled. CDP input coordinates are CSS pixels; on retina displays, screenshot pixel coordinates often need to be divided by `window.devicePixelRatio`.
- `evalraw` sends a command to the page session, not automatically to a nested preview execution context.

## Flow Format

Flow files are JSON arrays or `{ "steps": [...] }` objects. Keep them under `.verify-flows/`.

```json
[
  { "type": "waitSelector", "selector": ".composer textarea", "timeout": 10000 },
  { "type": "fill", "selector": ".composer textarea", "text": "你好，继续当前剧情。" },
  { "type": "click", "selector": ".composer button" },
  { "type": "waitEngineIdle", "timeout": 90000 },
  { "type": "engineState" },
  { "type": "auditLayout", "preset": "mobile" },
  { "type": "screenshot", "name": "flow-final.png" }
]
```

Supported step types:

- `wait`: `{ "ms": 1000 }`
- `waitSelector`: `{ "selector": ".foo", "timeout": 10000 }`
- `waitText`: `{ "text": "完成", "timeout": 10000 }`
- `waitExpr`: `{ "expr": "document.querySelectorAll('button').length > 0" }`
- `waitEngineIdle`: waits for an engine snapshot with `streaming=false`
- `fill`: sets React-controlled input or textarea values correctly
- `click`: DOM click by selector
- `scroll`: scrolls document or a selector
- `eval`: evaluates JavaScript in the preview frame
- `engineState`: dumps engine/debug snapshot
- `auditLayout`: runs layout audit
- `screenshot`: saves a screenshot

## Troubleshooting

- `ECONNREFUSED` on `9222`: Electron was not restarted after CDP was enabled, or `SEASHORT_CDP_PORT=0`.
- Target list has no SeaShort/Electron page: confirm the SeaShort app instance with the current project is running and CDP is enabled.
- Frame list has no obvious Vite preview frame: the WebIDE preview may be closed, not loaded, or using another port. Use `descriptor` and `inspect` to read runtime data and frame URLs, then pass `--frame-url <pattern>` for custom selection when needed.
- Screenshot is blank: wait for the preview selector, use `inspect`, then retry after the frame finishes rendering.
- Input does not change in React controlled fields: use the native `HTMLInputElement`/`HTMLTextAreaElement` value setter, then dispatch both `input` and `change` events. Direct `el.value = ...` can update the DOM while leaving React state unchanged.

## Upstream Inspiration

This project keeps a SeaShort-specific script rather than vendoring a generic browser skill. The expanded command surface intentionally follows the lightweight, no-Puppeteer approach of `pasky/chrome-cdp-skill` while preserving SeaShort-specific preview-frame selection, project-local screenshots, and lifecycle smoke tests.
